### 2026-10-10 · Brainstorm 启动与定稿

**用户关键原话（摘要）**：
- 用 Superpowers 模式给现有客服系统（ch01 纯对话底座）装上**查数据**的能力，用 Function Calling 让模型自己决定调什么工具。
- 建表以 `d:\knowweave\建表语句.md` 为准（`没问题`）。
- 功能范围：模型在聊天页问一句就触发工具链「决策 → 执行 → 回灌收敛」，**只做单轮**（调一次就收敛，不做 Agent Loop）。
- 五个工具：query_order / query_product / query_logistics（mock 随机造数、回显入参、不接真实接口不建表）、query_faq（LIKE 查 faq 表）、create_ticket（写 tickets + 会话状态置已转人工）。
- 落库：四张 MySQL 表（conversations / messages / tickets / faq），DB 是唯一真相源。
- 验收三条：① 问「订单 1001 的物流到哪了」→ 工具徽章 + 作答 ② 问「退货政策是什么」→ query_faq 命中 ③ 问「邮费是多少」→ query_faq 查不到、如实说（漏召回为预期，留 RAG）。
- 工作要求（沿用 ch01）：全程 Superpowers；非可单测任务（Prompt/数据）用标注样例/评估集替代 TDD；聊天页走 Vibe Coding；过程留痕 dev-notes/ch02.md；库/框架用法先 Context7 查最新文档；技术选型定死，有矛盾停下问。
- 安全约束（ch01 起持续生效）：密钥绝不打印、绝不入库，只在 `.env`。

**我的关键产出**：
- 设计 spec：`docs/superpowers/specs/2026-10-10-ch02-tool-calling-design.md`（11 节：目标/约束/架构/数据模型/工具定义/基础设施/SSE 协议/错误处理/测试策略/目录结构/验收）。
- 关键设计决策：① 四表 DDL 逐字对齐 `建表语句.md`；② `session_id`（API 层）= `str(conversations.id)`，首条消息传 null → 后端 INSERT 拿数字 id → 经 `{"type":"session"}` 回传，不背离 DDL 加列；③ 依赖注入：query_faq 注入 DB 会话、create_ticket 注入会话 + conversation_id，模型只填业务参数；④ SSE 新增 `tool_status` 事件；⑤ 单轮约束：决策用 `bind_tools().ainvoke()`，最终回答用**不绑工具**的裸 `astream()`（杜绝循环）。
